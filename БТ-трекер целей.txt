Автоматизация процедуры контроля качества данных по целям 
сотрудников 
Цель:  
Реализовать требования бизнес-заказчика по проекту «Автотрекинг целей B2B+» в части 
расчёта и визуализации процедуры контроля качества данных (ККД). 
 
Какую ключевую проблему должен решаем и что важно оптимизировать? 
Ключевая проблема – отслеживание качества данных, которые сотрудники банка заносят 
в модуле «Цели» в ПУЛЬСе. При наличии проблем в данных (некорректно заведенные 
цели / ключевые результаты) – процесс целеполагания работает неэффективно и топ-
менеджмент банка не может видеть реальной картины по работе над целями, которые 
ставит руководство банка. 
Что должно быть разработано в рамках проекта: 
1. Таблицы / VIEW / Функции и процедуры для реализации механизма ККД по 
существующим данным  
2. Endpoint-ы в существующих сервисах на Java для передачи на front-end результатов 
работы модуля ККД 
3. Страница для отображения результатов работы модуля – статистика / найденные 
проблемы / дельта с прошлым прогоном по данным 
 
Где и как будет использоваться результат разработки: 
1. В проекте «Автотрекинг целей B2B+» в АС Поток будет реализован модуль «ККД» в 
разделе «Автотрекер» - там руководители и администраторы системы проверяет 
качество данных на периодической основе (планируется еженедельно) 
 
Целевая аудитория: Кто будет использовать систему?  
Бизнес-администраторы системы «Автотрекинг целей B2B+», руководители штабов / 
ответственные за целеполагание в подразделениях в блоках B2B+. 
 
Сценарии использования (User Stories) 
Как пользователь сервиса я хочу видеть определенные количественные и качественные 
метрики по существующему набору данных (цели и ключевые результаты) с учётом 
каскадирования. Также хочу видеть динамику (дельту) по сравнению с предыдущим 
набором данных (полученных в прошлый раз). 
 
Какие данные могут быть предоставлены для реализации проекта:  
1. Доступ к кодовой базе проекта 
2. Доступ к тестовым данным по целям и ключевым результатам

Метрики оценки качества: 
1. Соответствие логики реализации поставленным требованиям 
2. 100% соответствие реализованного визуала предоставленным макетам 
 
Как процесс выглядит сейчас (AS IS): 
Процесс ККД сейчас считает технические метрики, без нужной визуализации. 
 
Как процесс должен выглядеть (TO BE): 
Подсчитываемые метрики должны соответствовать БТ, должен быть реализован 
требуемая страница для визуализации результатов работы модуля ККД. 
 
Технологический стек: 
Пример: 
– Java 
– React.js 
– PostgreSQL 
– LLM GigaChat 
 
Условия, необходимые для приемки результатов проекта: 
1. Решение в виде кода оформлено по требованиям команды 
2. Java сервис корректно собирается и устанавливается на ИФТ стенд 
3. Скрипты БД корректно выполняются (накат – откат – повторный накат) на ИФТ стенде 
4. Реализован требуемый интерфейс по предоставленному Storybook 
5. Реализация метрик соответствует требованиям
