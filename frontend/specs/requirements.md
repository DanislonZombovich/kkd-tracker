# Requirements Specification: Модуль ККД (Frontend React)

## 1. Назначение и контекст
Пользовательский интерфейс страницы модуля контроля качества данных (ККД) по целям и ключевым результатам в корпоративной системе управления целями «Автотрекинг целей B2B+».

## 2. Функциональные требования
1. **Контекст и навигация:**
   - Выбор подразделения из иерархического справочника (`TreeSelect` с отображением дерева подчиненности).
   - Выбор прогона (`Select` с отображением кода, даты снимка и статуса).
   - Индикация базы сравнения: показ прогона `compared_to_run_id` или отметки «Первый прогон».
2. **Сводка и карточки метрик:**
   - Карточки ключевых метрик (`clean_goals_share`, `cascade_coverage`, `critical_issues`, `issues_total`).
   - Отображение текущего значения, прошлого значения, дельты со стрелочным индикатором и тренда.
   - **Честность отображения дельты:**
     - Цвет определяется семантикой поля `trend` (`better` -> зелёный `#039306`, `worse` -> красный `#d43629`), а не простым математическим знаком.
     - Для первого прогона (`RUN-001`) при `previous = null` отображается явная подпись «нет данных для сравнения» в цвете `colorTextTertiary` (никаких нулей!).
3. **Панель дефектов и динамики:**
   - Счётчики по важности: Critical, Major, Minor с фильтрацией.
   - Счётчики дельты: Новые (`new`), Сохраняются (`persisting`), Исправленные (`resolved`).
   - **Интерактивность:** клик по любому счётчику дельты мгновенно фильтрует таблицу проблем.
4. **Таблица найденных дефектов:**
   - Серверная пагинация (`limit`, `offset`, `total`).
   - Фильтры по коду правила, уровню важности, статусу дельты и полнотекстовый поиск `q`.
   - Семантические бейджи с текстовыми подписями уровней и статусов (цвет не является единственным носителем смысла).
5. **Детальная карточка дефекта (модальное окно):**
   - Заголовок 20px / 600, скругление 28px, маска `rgba(50, 44, 38, 0.07)`.
   - Полное описание нарушения, фактическое и ожидаемое значение, рекомендация по исправлению.
   - Временная шкала (Timeline) истории фиксации проблемы по прогонам с честным отображением неудачных прогонов (при `present = null` или ошибке выводится статус сбоя без ложной отметки об исправлении).
6. **Граничные состояния:**
   - `RUN-006` (409 RUN_FAILED) — понятный предупреждающий экран с возможностью переключиться на последний успешный прогон.
   - `TX-NEW` (подразделение без целей) — информативный баннер «В подразделении нет активных целей».
   - Корректная обработка задержки загрузки и сетевых ошибок.

## 3. Критерии приёмки
- Полное визуальное соответствие токенам корпоративного `UI-KIT.md`.
- Чистая сборка TypeScript (`npm run build`) без ошибок.
- Быстрый запуск не более чем в 3 команды.
