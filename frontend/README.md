# Модуль контроля качества данных (ККД) по целям сотрудников — Frontend (React)

Пользовательский интерфейс модуля ККД для корпоративной системы «Автотрекинг целей B2B+».
Реализован на базе **React 18 + TypeScript + Ant Design 5** в строгом соответствии с корпоративным дизайн-китом [UI-KIT.md](../mock_api/UI-KIT.md).

---

## 1. Быстрый запуск (не более 3 команд)

### Вариант 1. Через Docker Compose
```bash
docker compose up --build
```
Интерфейс будет доступен по адресу: `http://localhost:3000`.

### Вариант 2. Локальный запуск (Node.js)
```bash
# 1. Установка зависимостей
npm install

# 2. Запуск dev-сервера
npm run dev
```
Приложение откроется на `http://localhost:3000`. По умолчанию настроен proxy на mock API (`http://localhost:8000`) или Java backend (`http://localhost:8080`). Адрес настраивается через переменную `VITE_API_BASE_URL` в `.env`.

## 2. Реализованный функционал

1. **Контекст и навигация:**
   - Выбор подразделения (`TreeSelect` с отображением иерархии `block` → `hq` → `unit`).
   - Выбор прогона из выпадающего списка (с датой, статусом и индикатором базы сравнения `compared_to`).
2. **Сводка метрик качества:**
   - Карточки с крупными числами (28px / 600) и формулами в тултипах.
   - **Честное отображение дельты:**
     - Цвет стрелки и бейджа вычисляется по полю `trend` из API (`better` → зелёный `#039306`, `worse` → красный `#d43629`, `same` → `#76726C`).
     - Направление дельты и оценка «лучше / хуже» не путаются со знаком числа (рост дефектов — это ухудшение!).
     - Для первого прогона (`RUN-001`) отображается «нет данных для сравнения» (не `0`).
3. **Панель дефектов и динамики:**
   - Разделение по уровням важности (Critical, Major, Minor).
   - Счётчики дельты (Новые, Сохраняются, Исправленные).
   - **Интерактивные фильтры:** клик по счётчикам Новые / Сохраняются / Исправленные мгновенно фильтрует таблицу проблем.
4. **Таблица найденных проблем:**
   - Серверная пагинация (`limit`, `offset`, `total`).
   - Фильтры по коду правила, важности, статусу дельты и полнотекстовый поиск `q`.
   - Наглядные теги с текстом и иконками (доступность a11y).
5. **Карточка проблемы (модальное окно):**
   - Радиус скругления 28px, заголовок 20px / 600, полупрозрачная маска `rgba(50, 44, 38, 0.07)`.
   - Блок рекомендации по исправлению дефекта, фактическое и ожидаемое значение.
   - Временная шкала (Timeline) истории фиксации проблемы по прогонам.
6. **Обработка граничных состояний:**
   - `RUN-006` (409 RUN_FAILED) — информативное предупреждение без падения интерфейса и кнопка перехода к последнему успешному прогону.
   - `RUN-001` (первый прогон) — корректный рендеринг нейтральных меток отсутствия сравнения.
   - `TX-NEW` (подразделение без целей) — информативный баннер об отсутствии целей.
