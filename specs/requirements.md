# Корпоративная спецификация требований: Модуль ККД («Автотрекинг целей B2B+»)

## 1. Введение
Настоящий документ определяет требования к модулю контроля качества данных (ККД) по целям и ключевым результатам сотрудников блока B2B+. Разработка ведется для четырех взаимосвязанных направлений:
1. **BA (Бизнес-анализ):** каталог бизнес-правил, дерево метрик, целевой процесс TO BE, регламент эскалации и приёмочные сценарии (Gherkin).
2. **SA (Системный анализ):** реляционная модель данных PostgreSQL, алгоритмы иерархической агрегации, правила сопоставления дельты и спецификация REST API.
3. **Backend (Java / Spring Boot 3):** изолированный движок правил, сервис расчета метрик и дельты, миграции Liquibase с откатом и REST-контроллеры.
4. **Frontend (React / Ant Design 5):** интерфейс руководителя и администратора, точно соответствующий корпоративному UI-киту, с честным отображением дельты и обработкой граничных состояний.

---

## 2. Каталог бизнес-правил ККД
1. `GOAL_NO_OWNER` (Critical) — цель без ответственного лица.
2. `GOAL_NO_KR` (Critical) — активная цель без ключевых результатов.
3. `KR_WEIGHTS_SUM` (Major) — сумма весов КР цели отличается от 100%.
4. `CASCADE_NO_PARENT` (Major) — некорневая цель без связи с целью вышестоящего уровня.
5. `KR_NO_TARGET` (Major) — ключевой результат без целевого значения.
6. `KR_STALE_PROGRESS` (Minor) — факт КР не обновлялся более 45 дней.

---

## 3. Метрики качества данных
- `clean_goals_share` (%): доля активных целей без единого замечания (рост — лучше).
- `cascade_coverage` (%): процент целей с корректной каскадной привязкой (рост — лучше).
- `critical_issues` (шт.): число критических замечаний (снижение — лучше).
- `issues_total` (шт.): общее число дефектов данных (снижение — лучше).

---

## 4. Критерии приёмки
- 100% покрытие приёмочных критериев на стенде.
- Корректная сборка и запуск через `docker compose up`.
- Выполнение миграций: накат → откат → повторный накат.
