# Модуль контроля качества данных (ККД) по целям сотрудников — Backend (Java)

Сервис модуля ККД в составе проекта «Автотрекинг целей B2B+». Реализует проверку качества данных по целям и ключевым результатам сотрудников в PostgreSQL, расчет метрик с учетом иерархического каскадирования подразделений, вычисление дельты между прогонами и REST API для интерфейса ККД.

---

## 1. Стек технологий
- **Язык и среда:** Java 21, OpenJDK
- **Фреймворк:** Spring Boot 3.3.5 (Spring Web, Spring Data JPA, Spring Validation)
- **База данных:** PostgreSQL 15+ (H2 in-memory в тестовом профиле)
- **Миграции БД:** Liquibase 4.27.0 с поддержкой отката (`rollback`)
- **Сборка и контейнеризация:** Maven, Docker, Docker Compose
- **Тестирование:** JUnit 5, AssertJ, Spring Boot Test

---

## 2. Быстрый запуск

### Вариант 1. Запуск через Docker Compose (одной командой)
Весь стек (PostgreSQL + миграции Liquibase + стартовые данные + Spring Boot сервис) поднимается командой:
```bash
docker compose up --build
```
Сервис будет доступен по адресу: `http://localhost:8080`.

### Вариант 2. Локальный запуск (Maven)
Требуется локальный PostgreSQL (параметры по умолчанию: БД `kkd_db`, пользователь `kkd_user`, пароль `kkd_secret`):
```bash
# 1. Запуск тестов
mvn clean test

# 2. Сборка и запуск сервиса
mvn spring-boot:run
```

## 3. Проверка наката, отката и повторного наката миграций

В проекте реализованы Liquibase changeSet с явными блоками `<rollback>`.
Проверка цикла **накат → откат → повторный накат**:

```bash
# 1. Накат миграций до актуальной версии
mvn liquibase:update

# 2. Откат последней миграции (002-seed-data)
mvn liquibase:rollback -Dliquibase.rollbackCount=1

# 3. Полный откат всех миграций (включая 001-init-schema)
mvn liquibase:rollback -Dliquibase.rollbackCount=1

# 4. Повторный накат миграций с нуля
mvn liquibase:update
```

## 4. Архитектура решения

1. **Изолированный движок правил (`KkdRuleEngine`):**
   * Логика правил (`ru.sber.kkd.rules.*`) полностью отделена от контроллеров, слоя API и прямого доступа к БД.
   * Каждое правило реализует интерфейс `KkdRule` и выполняет проверку над переданными неизменяемыми коллекциями сущностей:
     * `GOAL_NO_OWNER` (critical): цель без назначенного ответственного сотрудника;
     * `GOAL_NO_KR` (critical): активная цель без единого ключевого результата;
     * `KR_WEIGHTS_SUM` (major): сумма весов КР цели отличается от 100%;
     * `CASCADE_NO_PARENT` (major): цель уровня hq/unit не привязана к цели вышестоящего уровня;
     * `KR_NO_TARGET` (major): ключевой результат без целевого числового значения;
     * `KR_STALE_PROGRESS` (minor): факт КР не обновлялся более 45 дней.
   * Правила применяются только к активным целям (`status = 'active'`) и их ключевым результатам.

2. **Иерархический расчёт метрик подразделения (`MetricService` + `HierarchyService`):**
   * Метрики любого выбранного подразделения (например, департамента `HQ-CIB`) рассчитываются кумулятивно — по целям самого подразделения и всех его дочерних отделов (`descendants_or_self`).
   * Метрика `clean_goals_share` (%): отношение активных целей без замечаний ко всем активным целям в охвате.
   * Метрика `cascade_coverage` (%): отношение некорневых целей с корректной родительской связью ко всем некорневым целям.
   * Для подразделения без целей (`TX-NEW`) возвращается `null` для долевых метрик, что предотвращает деление на 0.

3. **Расчёт дельты между прогонами (`DeltaService`):**
   * Дефект идентифицируется стабильным отпечатком `fingerprint = rule_code + ":" + object_id` и SHA-1 хешем `id = "ISS-" + SHA1(fingerprint)[:10]`.
   * Дельта сопоставляет дефекты текущего прогона с базовым прогоном (`compared_to_run_id`):
     * `new`: возникшие в текущем прогоне;
     * `persisting`: сохраняющиеся из прошлого прогона;
     * `resolved`: исправленные (присутствовали в прошлом, отсутствуют в текущем).
   * **Граничное состояние:** у первого прогона (`RUN-001`) сравнение отсутствует — поля `previous`, `delta`, `delta_pct`, `trend` и счётчики дельты строго равны `null`, а не `0`.

## 5. Эндпоинты REST API

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/runs?limit=&offset=` | Список прогонов: статус, дата снимка, база сравнения, счётчики дефектов |
| `GET` | `/api/runs/{runId}` | Детали прогона |
| `GET` | `/api/kkd/summary?run_id=&unit_id=` | Сводка качества данных подразделения: метрики, дельта, тренд, дефекты по важности |
| `GET` | `/api/kkd/issues?run_id=&unit_id=&rule_code=&severity=&delta_status=&limit=&offset=` | Список проблем снимка с фильтрацией и пагинацией |
| `GET` | `/api/kkd/issues/{issueId}?run_id=` | Карточка проблемы с историей по прогонам (`history`) |
| `GET` | `/api/meta` | Справочник оргструктуры, правил, уровней важности и статусов дельты |
