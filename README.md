# Автоматизация процедуры контроля качества данных (ККД) по целям сотрудников («Автотрекинг целей B2B+»)

Комплексное решение тестового задания для отбора на проект блока «Технологии B2B» по всем четырем направлениям:
1. **BA (Бизнес-аналитик)**
2. **SA (Системный аналитик)**
3. **Backend (Java 21 / Spring Boot 3 / PostgreSQL / Liquibase)**
4. **Frontend (React 18 / TypeScript / Ant Design 5 / Corporate UI-Kit)**

## 1. Направление: Бизнес-анализ (BA)
Материалы находятся в каталоге `ba/`:
- **`Тестовое_задание_BA_решение.pdf`** (и `.md`):
  1. **Уточняющие вопросы к стейкхолдерам:** 10 структурированных вопросов по 4 блокам (бизнес-цели, правила, методология метрик, регламент эскалации).
  2. **Каталог бизнес-правил:** 4 базовых правила (`GOAL_NO_OWNER`, `GOAL_NO_KR`, `KR_WEIGHTS_SUM`, `CASCADE_NO_PARENT`) + 2 расширенных (`KR_NO_TARGET`, `KR_STALE_PROGRESS`) с классификацией критичности, объектом проверки и алгоритмом.
  3. **3 ключевые метрики качества данных:**
     - *Clean Goals Share* (% целей без замечаний, рост = лучше).
     - *Cascade Coverage* (% каскадированных целей, рост = лучше).
     - *Critical Issues Count* (число критических замечаний, снижение = лучше).
  4. **Целевой процесс TO BE:** BPMN-описание шагов от ночного ETL-среза до закрытия дефектов; 4-уровневый регламент эскалации (L1 Автор -> L2 Руководитель -> L3 C-Level -> L4 Блокировка премирования).
  5. **Критерии приёмки (Acceptance Criteria):** 4 сценария на языке **Gherkin** (первый прогон `RUN-001`, расчет дельты `RUN-002`, обработка упавшего прогона `RUN-006`, пустое подразделение `TX-NEW`).
  6. **Мотивация:** профессиональный интерес к продуктовой аналитике B2B и выстраиванию доверия к данным целеполагания.

## 2. Направление: Системный анализ (SA)
Материалы находятся в каталоге `sa/`:
- **`Тестовое_задание_SA_решение.pdf`** (и `.md`):
  1. **Реляционная модель данных PostgreSQL:** 6 таблиц (`organizational_units`, `goals`, `key_results`, `kkd_rules`, `kkd_runs`, `kkd_issues`) с типами данных, первичными/внешними ключами, check-констрейнтами и индексами + текстовая ER-диаграмма.
  2. **Формализация бизнес-правил в SQL:** точные SQL-запросы выявления дефектов для каждого из правил с защитой от NPE и деления на 0.
  3. **Алгоритм иерархической агрегации метрик:** рекурсивный Common Table Expression (CTE) для обхода дерева оргструктуры вниз от выбранного узла и расчет агрегированных метрик.
  4. **Спецификация расчета дельты:**
     - Дедупликация и стабильный отпечаток: `fingerprint = SHA1(rule_code || ':' || object_id)`.
     - База сравнения: последний успешно завершенный прогон (`status = 'completed'`).
     - Статусы дефектов: `NEW`, `PERSISTING`, `RESOLVED`.
     - Обработка `RUN-001`: возвращает `null` в полях дельты (не путать с нулем!).
  5. **REST API спецификация (OpenAPI 3.0 / YAML):** контракты для `/api/runs`, `/api/kkd/summary`, `/api/kkd/issues`, `/api/kkd/issues/{id}` с примерами запросов/ответов и единым форматом ошибок `{"error": {"code", "message"}}`.
  6. **Граничные случаи и мотивация:** детальный разбор 6 edge cases и профессиональная мотивация.

## 3. Направление: Backend (Java 21 / Spring Boot 3)
Реализован полноценный production-ready микросервис в каталоге `backend/`:
- **Стек:** Java 21, Spring Boot 3.3.5, Spring Data JPA, Liquibase, PostgreSQL 16, H2 (для тестов), Lombok, Jakarta Validation.
- **Миграции Liquibase:**
  - `001-init-schema.xml`: создание таблиц, индексов и связей. Содержит полные секции `<rollback>`.
  - `002-seed-data.xml`: 5 подразделений с иерархией, 24 цели, 29 ключевых результатов, 6 правил ККД, 2 прогона (`RUN-001`, `RUN-002`) и предрассчитанные дефекты. Содержит `<rollback>`.
- **Изолированный движок правил (`KkdRuleEngine`):**
  - Интерфейс `KkdRule` с сигнатурой `List<DiscoveredIssue> evaluate(KkdExecutionContext ctx)`.
  - Реализованы правила: `GoalNoOwnerRule`, `GoalNoKrRule`, `KrWeightsSumRule`, `CascadeNoParentRule`, `KrNoTargetRule`, `KrStaleProgressRule`.
- **Иерархическая агрегация и Дельта:**
  - `HierarchyService`: рекурсивный обход поддерева подразделения (например, выбрав `HQ-CIB`, получаем метрики по `HQ-CIB`, `DIR-CRED`, `TX-NEW`).
  - `DeltaService`: вычисление дельты относительно предыдущего успешного прогона, сопоставление отпечатков, идентификация решенных дефектов (`RESOLVED`).
- **REST Endpoints:**
  - `GET /api/runs` — список прогонов ККД.
  - `GET /api/units` — дерево/список подразделений.
  - `GET /api/rules` — каталог правил.
  - `GET /api/kkd/summary?runId=...&unitId=...` — агрегированные метрики, дельта и разбивка.
  - `GET /api/kkd/issues?runId=...&unitId=...&status=...&severity=...&ruleCode=...&search=...&page=0&size=20` — фильтрация и пагинация замечаний.
  - `GET /api/kkd/issues/{id}` — детализация замечания и история по прогонам.
- **Тестирование (22 теста, 100% pass):**
  - Пограничные тесты правил ККД (`KrWeightsSumRuleTest`, `GoalNoOwnerRuleTest`, `CascadeNoParentRuleTest`).
  - Тесты метрик и иерархии (`MetricServiceTest`).
  - Тесты дельты и сопоставления (`DeltaServiceTest`).
  - Интеграционные тесты Spring Boot (`KkdApplicationTests`).
  - Тест жизненного цикла миграций: **накат → откат → повторный накат** (`LiquibaseRollbackTest`).

## 4. Направление: Frontend (React 18 / TypeScript / Ant Design 5)
Реализован интерфейс в каталоге `frontend/`:
- **Корпоративный стиль (`UI-KIT.md`):**
  - Теплая гамма: фон страницы `#f7f3f0`, фон карточек `#fefcfa`, основной цвет `#056cfd`, ошибки `#d43629`, успех `#039306`.
  - Шрифт Inter, скругления карточек и модалок `borderRadius = 28px`, тени `0 2px 8px rgba(49, 41, 33, 0.06)`.
- **Компоненты:**
  - `Header`: селекторы прогона (с бейджами статуса) и подразделения (с иерархическими префиксами).
  - `MetricCards`: 4 карточки метрик с честным отображением динамики (дельта с префиксом `+`/`-`, стрелки направления, цвет бейджа зависит от бизнес-направления метрики `higher_is_better`, для первого прогона отображается тег «Базовый срез»).
  - `BreakdownBar`: интерактивная плашка распределения статусов (Новые, Сохраняются, Устранены) с возможностью клика для фильтрации таблицы.
  - `IssuesTable`: пагинированная таблица дефектов с фильтрами по статусу дельты, критичности, правилу и текстовым поиском.
  - `IssueModal`: модальное окно с деталями дефекта, объектом проверки, конкретными рекомендациями по исправлению и таймлайном истории по прогонам.
  - `ErrorAlert` и `EmptyUnitAlert`: баннеры для граничных состояний (ошибка упавшего прогона 409 `RUN-006`, предупреждение о пустом подразделении `TX-NEW`).

## Запуск проекта

### Вариант 1: Полный запуск через Docker Compose (Рекомендуемый)

Требования: установлен Docker и Docker Compose.

```bash
# Клонировать/перейти в директорию проекта
cd /home/danislon_zombovich/.gemini/antigravity/scratch/kkd_tracker

# Запустить все сервисы (PostgreSQL + Backend + Frontend)
docker compose up --build -d

# Проверить статус контейнеров
docker compose ps
```

Доступные адреса:
- **Frontend UI:** `http://localhost:3000`
- **Backend REST API:** `http://localhost:8080/api/runs`
- **PostgreSQL:** `localhost:5432` (db: `kkd_db`, user: `kkd_user`, pass: `kkd_secret`)

---

### Вариант 2: Локальный запуск сервисов

#### 1. Запуск БД (PostgreSQL)
```bash
docker run -d --name kkd-postgres -p 5432:5432 \
  -e POSTGRES_DB=kkd_db \
  -e POSTGRES_USER=kkd_user \
  -e POSTGRES_PASSWORD=kkd_secret \
  postgres:16-alpine
```

#### 2. Запуск Backend
```bash
cd backend
# Запуск тестов (включая проверку накат-откат-повторный накат)
mvn clean test

# Сборка jar
mvn clean package -DskipTests

# Запуск приложения
java -jar target/kkd-tracker-backend-1.0.0.jar
```

#### 3. Запуск Frontend
```bash
cd frontend
npm install
npm run build
npm run dev
```
Фронтенд запустится на `http://localhost:5173` (или `3000` в docker).
